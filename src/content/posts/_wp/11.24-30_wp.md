## [HDCTF 2023]easy_re

die查壳发现为upx加壳![](images/Pasted%20image%2020251129221523.png)  
脱壳后ida查看
```c
int __fastcall main(int argc, const char **argv, const char **envp)
{
  int i; // [rsp+2Ch] [rbp-4h]

  _main(argc, argv, envp);
  base64(
    a,                                          // "SERDVEZ7WTB1X2hAdjJfL1wvXEA1N2VyM2RfN2hlX3IzdjNyczN9"
    encode_a);
  puts_0("Please input your flag:");
  scanf("%s", flag);
  for ( i = 1; i <= 32; ++i )
    f3(flag);
  base64(flag, encode_flag);
  if ( !strcmp(encode_flag, a) )                // "SERDVEZ7WTB1X2hAdjJfL1wvXEA1N2VyM2RfN2hlX3IzdjNyczN9"
    puts_0("Congratulations! You get the flag");
  else
    puts_0("Sorry,try again");
  return 0;
}
```
>[!note] 代码分析
>1. func函数点开，发现是base64加密函数，我这里就直接改名为base64了![](images/Pasted%20image%2020251129222809.png)
>2. 分析f3函数
>```c
>l = strlen(s);
>  for ( i = 0; i < l / 2; ++i )
>  {
>    t = s[i];
>    s[i] = s[l - i - 1];
>    s[l - i - 1] = t;
>```
>发现是第i位和第l-i-1位互换  
>举例便于分析：若8长度字符串数组，则0<->7，1<->6, 2<->5, 3<->4,得出结论，f3函数就是将字符串进行对称互换  
>3. 那么flag在经过32次对称互换后，字符串顺序保持不变 //其实就是用来增加逆向代码分析难度的，无实际作用  
>4. 最后经过base64加密的flag和原来的a进行校验

所以直接对a进行base64解码即可得到flag![](images/Pasted%20image%2020251130011722.png)
